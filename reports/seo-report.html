01 — Executive Summary

SEO is a significant growth lever for Trip Cooks — currently underleveraged.

Trip Cooks is a Next.js 14 travel booking platform with solid technical foundations (Vercel deployment, image optimisation, dark mode, analytics), but prior to this audit it had no page-specific metadata, misleading image alt text being picked up by Google as a sitelink, and several structural issues that were suppressing organic visibility.

The most visible symptom was Google showing "Hamburger-menu" as a sitelink in search results for the query "tripcooks" — a direct consequence of Google falling back to the alt="hamburger-menu" image attribute when no meaningful page-specific content signal was available.

Key Finding All pages shared one generic title and description from the root layout. Individual pages had no unique metadata signals, making it impossible for Google to create meaningful sitelinks or rich snippets.

This report documents the pre-existing state, the fixes applied in this session, and the remaining work needed to achieve strong organic visibility for a travel brand in a competitive niche.

04 — Fixes Applied in This Audit

Changes Made to the Codebase

1. Fixed hamburger menu image alt text

Fixed

Changed alt="hamburger-menu" to alt="Open navigation menu" on both light and dark variants of the mobile navigation icon in components/ui/mobile-nav.tsx. This removes the signal Google was using to label the sitelink "Hamburger-menu" in brand search results.

2. Added per-page metadata via layout.tsx files

Fixed

Created individual layout.tsx server components for all "use client" page routes, each exporting unique metadata (title + description). This is the correct Next.js App Router pattern for adding metadata to client component pages.

Files created: app/home/layout.tsx, app/about/layout.tsx, app/trips/layout.tsx, app/private-trips/layout.tsx, app/cart/layout.tsx, app/checkout/layout.tsx, app/payment-success/layout.tsx

3. Added metadata directly to server component pages

Fixed

Added export const metadata directly to pages that were already server components: app/contact/page.tsx, app/legal/page.tsx, app/privacy/page.tsx, app/terms/page.tsx.

4. Excluded transactional pages from indexing

Fixed

Added robots: { index: false } to the metadata for /cart, /checkout, and /payment-success to prevent Google from indexing pages that have no SEO value and waste crawl budget.

05 — Remaining Issues & Recommendations

What Still Needs to Be Done

Critical — Do These First

A. Add generateMetadata to dynamic trip pages

Not Done

/trips/[id]/[name] pages are the highest-value SEO pages (specific trip destinations) but currently have no unique metadata. Implement generateMetadata in a server-side wrapper component to generate title, description, and Open Graph tags from Contentful trip data.

Example title pattern: "Bali Group Trip 2026 | Trip Cooks"
Example description: "Join the Trip Cooks group trip to Bali — 7 days of curated experiences, from £X deposit."

B. Add Open Graph & Twitter Card metadata

Not Done

None of the pages have openGraph or twitter metadata. This means every WhatsApp, Instagram, and Twitter share of a trip link shows a blank or generic preview. For a travel brand, social sharing is a critical acquisition channel.

Add to root layout metadata as defaults, then override per page and per trip:

openGraph: { title, description, images: [{ url: tripImageUrl }], type: 'website' }

C. Generate sitemap.xml

Not Done

Create app/sitemap.ts using Next.js's built-in sitemap support. Include all static routes and dynamically fetch trip URLs from Contentful to include all /trips/[id]/[name] pages. Submit to Google Search Console after deployment.

Exclude: /cart, /checkout, /payment-success, /api/*

D. Create robots.txt

Not Done

Create app/robots.ts to define crawl rules. Disallow: /api/, /cart, /checkout, /payment-success. Point Sitemap: to your production sitemap URL.

Important — Do These Second

E. Add JSON-LD structured data for trips

Not Done

Implement TouristTrip or Event schema on trip detail pages to enable rich results in Google (star ratings, price ranges, dates). This can significantly improve SERP click-through rates for high-intent travel searches.

Also consider Organization and WebSite schema on the home page.

F. Reconsider URL structure — /home vs /

Not Done

The site redirects / → /home, which means the canonical home URL is tripcooks.tours/home. This is unusual and splits link equity. Consider making / the true home page, or at minimum ensure all internal links point to /home consistently so Google understands the intended canonical.

G. Fill in thin content pages

Not Done

/privacy currently renders only the text "Privacy" and /terms renders only "Terms and Conditions" — these are placeholder pages with no real content. The actual policy content lives in /legal. Either redirect these pages to /legal, or add the full policy content to each.

H. Add canonical URLs to metadata

Not Done

Add alternates: { canonical: 'https://tripcooks.tours/[path]' } to each page's metadata. This prevents duplicate content issues caused by URL variations (trailing slashes, query parameters, etc.).

Longer Term — Content & Authority

I. Add a blog / travel guides section

Recommended

The site currently has no content marketing. Travel is an extremely competitive SEO space. Adding destination guides, packing lists, or group travel tips would create opportunities to rank for informational queries and drive top-of-funnel traffic that converts to trip bookings.

J. Verify site in Google Search Console & submit sitemap

Recommended

Once the sitemap is generated, submit to Google Search Console at search.google.com/search-console. Monitor for crawl errors, coverage issues, and Core Web Vitals. This is the primary tool for understanding how Google sees the site.
