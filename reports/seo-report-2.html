01 — Executive Summary

Significant SEO improvements shipped in two sessions.

Between the two audit sessions conducted on 17 February 2026, the Trip Cooks website went from having no per-page SEO signals to a fully implemented on-page SEO foundation. All 12 action items from the v1 report in the High and Important categories have been completed.

What was fixed 13 pre-existing issues resolved across two sessions: misleading alt text, missing per-page metadata, robots.txt, sitemap.xml, Open Graph tags, Twitter Cards, canonical URLs, JSON-LD structured data (TouristTrip + Organization + WebSite), thin content pages redirected, and decorative icon alt text corrected.

The "Hamburger-menu" sitelink in Google Search results will resolve automatically once Google re-crawls the site — typically within 2–6 weeks. With the sitemap now live, submitting it to Google Search Console will accelerate this process.

The remaining open items are editorial and strategic in nature (Google Search Console setup, OG image assets, blog content), and cannot be resolved through code changes alone.

03 — All Changes Implemented

Complete log of SEO changes across both sessions

Session 1 — Initial Fixes

Hamburger menu alt text corrected

Done

Changed alt="hamburger-menu" → alt="Open navigation menu" on both light and dark variants in components/ui/mobile-nav.tsx. This removed the signal causing Google to display "Hamburger-menu" as a sitelink.

Per-page metadata via layout.tsx files (7 routes)

Done

Created layout.tsx server components for all "use client" page routes: /home, /about, /trips, /private-trips, /cart, /checkout, /payment-success.

Metadata added directly to server-component pages

Done

Exported metadata directly from /contact, /legal, /privacy, /terms.

Cart, Checkout & Payment-success excluded from indexing

Done

robots: { index: false } added to the three transactional page layouts.

Session 2 — Full SEO Implementation (17 Feb 2026)

robots.txt — app/robots.ts

Done

Created app/robots.ts. Disallows /api/, /cart, /checkout, /payment-success. Points Sitemap directive to https://tripcooks.tours/sitemap.xml.

sitemap.xml — app/sitemap.ts

Done

Created app/sitemap.ts. Generates all static routes with correct changeFrequency and priority values, then dynamically fetches every trip from Contentful via Apollo to include all /trips/[id]/[name] URLs. Falls back to static routes if the Contentful fetch fails.

generateMetadata for dynamic trip pages — app/trips/[id]/[name]/layout.tsx

Done

Created a server-component layout that fetches the trip from Contentful by id and generates: unique title, description (from trip's description field), canonical URL, Open Graph image (trip's first banner image), Open Graph URL, and Twitter Card with image.

Example title: "Paris, France Group Trip | Trip Cooks"

TouristTrip JSON-LD on trip detail pages

Done

The trip detail layout also renders a TouristTrip schema script tag with: name, description, startDate, endDate, image, offers (deposit price in GBP), and provider (Trip Cooks organisation). This makes trip pages eligible for rich results in Google.

Organization + WebSite JSON-LD on home page

Done

Home layout now renders two JSON-LD scripts: Organization (name, URL, logo, Instagram and TikTok sameAs) and WebSite (with SearchAction pointing to trips search). This enables brand recognition in Knowledge Graph and Sitelinks Search Box.

metadataBase set in root layout

Done

Added metadataBase: new URL("https://tripcooks.tours") to root layout metadata. This is required for all relative OG image URLs to resolve correctly. Also added default openGraph (siteName, locale) and twitter (card type) blocks that all pages inherit.

Open Graph + Twitter Card metadata on all indexable pages

Done

Added openGraph (title, description, url, type) and twitter (card: summary_large_image, title, description) to every indexable page: /home, /about, /trips, /private-trips, /contact, /legal, and all dynamic trip pages.

Canonical URLs on all indexable pages

Done

Added alternates: { canonical: "https://tripcooks.tours/[path]" } to every indexable page's metadata. Dynamic trip pages generate their canonical from params.id and params.name.

Thin /privacy and /terms pages redirected to /legal

Done

Replaced the placeholder pages ("Privacy" and "Terms and Conditions" stubs) with redirect("/legal"). Both pages now forward to the full policy content at /legal, eliminating thin content pages from the index.

Social icon alt text fixed

Done

Changed hardcoded alt="instagram-logo" and alt="social-media-icon" to dynamic alt={social.name} in components/ui/mobile-nav.tsx. Icons now output alt="Instagram" and alt="Tiktok".

contact/page.tsx import order fixed

Done

Resolved a linter-introduced ordering issue where import statements appeared after the export const metadata declaration, which is invalid JavaScript module syntax.

06 — Remaining Recommendations

What's Left — Non-Code Actions & Future Improvements

A. Verify site in Google Search Console & submit sitemap

Not Done — Action Required

Go to search.google.com/search-console, add tripcooks.tours, verify ownership (DNS TXT record via Vercel is simplest), then submit https://tripcooks.tours/sitemap.xml. This is the single most impactful non-code action and should be done immediately after deploying the current changes.

B. Create a dedicated OG image for static pages

Recommended

Pages like /home, /about, /trips, and /private-trips have Open Graph metadata set but no OG image. When these links are shared on WhatsApp, Twitter, or LinkedIn, the preview will have no image. Create a branded 1200×630 JPG/PNG (e.g. logo + tagline on brand background) and add it to public/og-default.jpg, then reference it in each layout's openGraph.images.

C. Add Review / AggregateRating schema to trip pages

Recommended

Trip Cooks already has customer reviews in the CMS. Adding AggregateRating to the TouristTrip JSON-LD on trip detail pages could enable star ratings to appear directly in Google search results, significantly improving click-through rates.

D. Add FAQPage schema to /home or trip pages

Recommended

The home page has an FAQ section. Adding FAQPage JSON-LD would make these questions eligible to appear as expandable FAQ rich results in Google, taking up more SERP real estate without additional clicks required.

E. Reconsider the /home URL structure

Consider

The canonical home page is tripcooks.tours/home rather than tripcooks.tours/. While the redirect from / is in place, this is unconventional. Backlinks from external sites will typically point to tripcooks.tours (root), which redirects, diluting link equity slightly. Migrating the home page to / would be cleaner long-term, but requires careful testing of all internal links.

F. Add a blog or destination guides section

Long-term

Trip Cooks currently has no content marketing. Travel is one of the most competitive SEO niches. Adding destination guides, group travel tips, or packing list articles creates opportunities to rank for informational queries ("best group trips to Bali", "group travel tips UK") that feed top-of-funnel traffic into the booking flow. This is the highest long-term lever for organic growth.

G. Audit all image alt text across page components

Low priority

The nav icons have been fixed, but a full audit of image alt text across all _components directories is recommended to ensure complete consistency. Decorative images should use alt=""; content images should describe what's shown.
