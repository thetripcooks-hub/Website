1
Week 1
Setup & Design System
Completed
Established: Design Tokens Theme System Typography Navigation Footer UI Component Library CI / CD Pipeline Stripe Scaffolding
What was established
  • UI Component Library: Complete set of reusable components — Button, Card, Carousel, Dialog, Drawer, Accordion, Input, Select, Textarea, Form, Pagination, Tooltip, Skeleton and more — built and in use under components/ui/.
  • Theme System: Light / Dark mode implemented via CSS custom properties, with a mode-toggle component wired into the root app layout and persisted across sessions.
  • Typography: Plus Jakarta Sans (body and labels) and Ogg TRIAL (display headings) integrated via app/font.ts and app/fonts/.
  • Navigation: Responsive navbar, mobile-nav, and mobile-page-header components complete and verified across all breakpoints.
  • Footer: Footer component built and wired into the root layout site-wide.
  • Stripe Scaffolding: Checkout session API route, Stripe-powered payment component, and currency toggle integrated into the app.
  • CI / CD Pipeline: Automated build pipeline active on thetripcooks-hub/Website with build triggers on merge to staging and main.
Outcome Full component library live · Light/dark theme toggle functional · Design tokens applied site-wide · CI/CD pipeline operational
2
Week 2
Homepage & Trip Discovery
In Progress
Pages: Homepage Current Trips Trip Details 🌙 Light + Dark — trips pages   Contentful: Space Setup Trip Content Type Page Content Type API Integration
Implementation progress
Completed
  • Homepage: All sections implemented — Hero, Search UI, Featured Trip card, Services carousel, Upcoming Trips grid, Blog Callout, FAQ accordion, Gallery (The Tripcooks Experience), Reviews/Testimonials, Community preview, Why Choose Us, and Travel Chef.
  • Current Trips: Trip card component (destination) and sort/filter controls (sort-by) built and functional.
  • Trip Details: Full detail page at /trips/[slug] — Itinerary, What's Included, Payment Card, Payment Terms, Trip Info, Travel With Owners, Location Views, and See More Drawer all implemented.
  • SEO: Improvements applied across all existing routes — meta tags, structured data, sitemap, and robots.txt.
Remaining
  • Homepage Redesign Polish: Featured Trip card and Upcoming Trips sections being refined to match new Figma designs. Active on the feature/homepage-redesign branch.
  • Dark Mode Verification: Current Trips and Trip Details pages need to be verified against the new Figma dark mode specs.
  • Trip Listing States: "Sold Out" and "Past Trip" UI state variants to be implemented on the listing page.
  • Review Module: 3rd-party review module integration on the Trip Details page.
Contentful — to be completed this phase
  • Space Setup: Provision Contentful space and configure production and preview environments.
  • Trip Content Type: Define fields — title, slug, dates, price, hero image, itinerary (rich text), included/not-included items, status (active / sold-out / past), group size, and duration.
  • Page Content Type: Shared SEO fields (meta title, description, OG image) linkable from all routes.
  • API Integration: Connect Contentful SDK to the trip listing and detail pages; configure preview environment and build webhooks.
  • Initial Data: Populate at least 3 active trips, 1 sold out, and 1 past trip for testing.
QA criteria
  • Homepage: Visual output matches Figma design at 375, 768, and 1440px breakpoints.
    • Carousel/slider — swipe, keyboard navigation, and autoplay correct
    • FAQ accordion — open/close logic, keyboard accessible
    • Lighthouse baseline score recorded (Performance, SEO, Accessibility)
  • Current Trips: Sort and filter return correct results; filter state persists in URL.
    • Sold Out state — booking CTA disabled, messaging correct
    • Past Trip state — no active CTA visible, SEO meta tags present
  • Trip Details: Dynamic content from Contentful renders correctly in production and preview.
  • Dark Mode: Current Trips and Trip Details verified against new Figma specs in dark mode.
  • Contentful: Data flows correctly end-to-end; preview environment resolves unpublished changes.
Deliverables Homepage redesign live on staging · Current Trips + Trip Details updated to new designs · Contentful space live with trip data flowing · Dark mode verified
3
Week 3
Booking Flow & Supporting Pages
Not Started
Pages: Cart Checkout Confirmation Screen About How to Book Contact Past Trips Sold Trip Detail Legal / Travel Policy 🌙 Light + Dark — all pages

Note: Page shells already exist in the codebase (/cart, /checkout, /about, /contact, /legal, /private-trips). This phase updates each to match the new Figma designs rather than building from scratch.

Implementation
  • Cart: Update UI to new design — trip summary card, seat count selector, price breakdown, remove and edit actions.
  • Checkout: Rework multi-step flow to new mobile-first design; Stripe payment form components updated to match new UI.
    • Streamlined mobile-first payment interface
    • Guest vs. logged-in checkout paths handled
  • Confirmation Screen: New design applied to /payment-success — success message and next-steps guidance.
  • About: Update to new layout — brand mission section, adventurers/team section, and visual storytelling.
  • How to Book a Trip: Implement step-by-step guide page (currently under /private-trips); update to new layout with numbered steps.
  • Contact: Update Smart Form UI with conditional field logic — General Inquiry vs. Private / Bespoke Trip request paths.
  • Past Trips: New listing layout applied; SEO-safe archived trip cards with no active booking CTAs.
    • Sold Trip Detail — individual page variant for an archived trip
  • Legal / Travel Policy: Long-form text page updated to new design, covering /legal, /terms, and /privacy.
  • Dark Mode: Light + Dark mode applied and verified across all 9 pages in scope.
Contentful
  • About: Body copy, team/adventurer bios, and image assets entered as structured content entries.
  • How to Book: Step content modelled as ordered entries and populated.
  • Past Trips: Archived status flag set; SEO meta fields populated per trip entry.
  • Legal: Full rich text content for Travel Policy, Terms, and Privacy entered into Contentful.
  • Contact Form: Recipient routing and field labels managed via CMS rather than hardcoded.
QA criteria
  • Booking Flow: E2E test — add trip → cart → checkout → confirmation — passing in Stripe test mode.
    • Successful payment, declined card, and card validation error states all handled
    • Cart contents persist across page refresh and navigation
    • Mobile checkout — tap targets correct, virtual keyboard does not obscure inputs
  • Smart Form: Conditional fields display and hide correctly based on inquiry type; submission routes to correct recipient.
  • Past Trips: Confirmed — no active booking CTAs present; correct SEO meta tags in document head.
  • Dark Mode: Verified across all 9 pages in this phase.
Deliverables Full booking E2E passing in Stripe sandbox · All 9 pages updated to new designs · Smart Form logic verified · Dark mode QA'd
4
Week 4
Blog, Community & Dark Mode Polish
Not Started
New routes: Blog Landing Blog List View Blog Article Community Landing Community Article 🌙 Light + Dark — all templates   Also: Dark Mode Audit — All 11 Pages Site-wide SEO Pass

Note: Blog and Community are new routes with no existing page shells — /blog and /community directories will be created from scratch in this phase.

Implementation
  • Blog Landing Page: Travel guides grid with category/tag filtering.
  • Blog List View: Filtered/selected view with tag and category-based filtering and correct URL state.
  • Blog Article Template: Readable long-form layout — author block, related articles, sharing — optimised for SEO and reading experience.
  • Community Landing Page: Interview and Q&A card grid.
  • Community Article Template: Traveller testimonial layout with portrait, quote, trip reference, and social proof elements.
  • Dark Mode Audit: All 11 pages reviewed — inconsistencies resolved, colour contrast confirmed across both themes.
  • SEO Pass: Structured data (JSON-LD), Open Graph tags, and meta descriptions audited and completed across all routes.
Contentful
  • Blog Post Content Type: Title, slug, author, hero image, body (rich text), tags, category, published date, and SEO fields.
  • Community Article Content Type: Interviewee name, Q&A body (rich text), portrait image, linked trip reference, and publication date.
  • Taxonomy: Categories and tags defined to support Blog filter view and URL-based filtering.
  • Initial Content: At least 3 blog posts and 3 community articles populated with real content.
  • Publish Workflow: Draft → Review → Published states configured with preview URL support for content editors.
  • SEO Fields: Meta title, description, and OG image enforced as required fields on all content types.
QA criteria
  • Blog Article: Rich text formatting, inline images, and typography correct at all breakpoints.
    • Blog list and filter view — tag filtering returns correct results; pagination loads correctly
  • Community Article: Testimonial structure, images, and traveller profile display correctly.
  • Empty States: No posts / no community content — appropriate fallback UI shown in each case.
  • SEO Audit: Meta tags, JSON-LD structured data, and Open Graph tags verified on all 11 routes.
  • Dark Mode: Full pass across all 11 pages — no unthemed elements, no colour contrast failures.
  • Contentful Workflow: End-to-end verified from draft through to live content on staging.
Deliverables Blog + Community templates live · Dark mode audit complete across all 11 pages · SEO pass done · Contentful publish workflow verified
5
Week 5
QA, Edge Cases & Launch
Not Started
Scope: All 11 Pages 404 Page No Results States Success Screens Cross-Browser Mobile Devices Core Web Vitals WCAG 2.1 AA UAT
Implementation
  • 404 Page: On-brand "Page Not Found" screen with links back to Homepage and Trips.
  • No Results States: Trips listing, Blog, and Community pages all handle zero-result scenarios with appropriate fallback UI.
  • Success Screens: Booking confirmation (/payment-success) and contact form submission success screen — final designs applied.
  • Copy Review: Final proofreading and tone-of-voice consistency pass across all 11 pages.
  • Staging Validation: All routes, redirects, and environment variables confirmed correct on staging.
  • Launch Checklist: DNS, CDN configuration, analytics integration, and error monitoring confirmed before go-live.
Contentful — handoff
  • Content Review: All entries proofread and approved for production by the content team.
  • Images: All images optimised for web; alt text added and verified across all entries.
  • Published State: All entries confirmed in published state — no content remaining in draft ahead of UAT.
  • Permissions: Editor roles configured correctly for the client content team.
  • Onboarding: Contentful walkthrough delivered to content editors ahead of launch.
QA criteria
  • Cross-Browser: Chrome, Safari, Firefox, and Edge on desktop — key flows verified on each.
  • Mobile Devices: iOS Safari and Android Chrome tested at phone and tablet sizes across all key pages.
  • Core Web Vitals: LCP, CLS, and INP meet target thresholds on all high-traffic pages.
    • Homepage, Trips listing, Trip Detail, and Checkout prioritised
  • Accessibility: WCAG 2.1 AA compliance verified — keyboard navigation, visible focus states, and ARIA labels correct throughout.
  • Link Integrity: Full site crawl completed; all internal and external links confirmed working.
  • UAT Sign-off: Stakeholder approval on staging obtained before any production deployment.
  • Security Review: No API keys or secrets exposed client-side; HTTPS enforced; Content Security Policy headers reviewed.
Deliverables All edge cases built and QA'd · Cross-browser and mobile testing passed · WCAG 2.1 AA confirmed · Contentful handed off · UAT signed off · Site ready for production
